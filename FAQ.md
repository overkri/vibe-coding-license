# FAQ

## Is VCL a license?

No. It is a manifesto. It grants no rights to use, copy, modify, or distribute code.

## Does VCL grant me any rights?

No. The code's real license does that. If a project has no real license, the default is all rights
reserved.

## Can I use VCL in a commercial project?

Yes, as a manifesto. The manifesto text is CC0-1.0. The code is governed by the project's real
license, so check that license for commercial terms.

## Is VCL OSI-approved?

No. It is not a license, so it cannot be OSI-approved.

## Will GitHub show a VCL badge?

No. GitHub's license detector recognizes standard licenses such as MIT and Apache-2.0. Keep a
standard `LICENSE` file; add `VIBE.md` next to it.

## Can I modify or translate VCL?

Yes. The manifesto text is CC0-1.0. Attribution is appreciated but not required.

## Can I use the phrase バイブコーディング、ビッチ❗️?

Yes, the text is CC0-1.0. It is edgy by design; use your judgment in professional contexts.

## What is LicenseRef-VibeCoding-1.0?

It is a custom SPDX license reference for tooling that needs an identifier for the manifesto. It
is not a standard license, not OSI-approved, and not a grant of rights. The code's SPDX license
should remain `MIT` or `Apache-2.0`. If you use REUSE, put the manifesto in
`LICENSES/LicenseRef-VibeCoding-1.0.txt`.

## Should I write `MIT AND LicenseRef-VibeCoding-1.0`?

No. That would imply the manifesto is a license condition. Keep the code license as `MIT` and
reference VCL separately as a manifesto.

## Can I apply VCL to a learner project?

Yes, as a mindset. Teach learners to add a real license first. See
[FOR-LEARNERS.md](./FOR-LEARNERS.md).

## Is "Vibe Coding" your term?

No. The term was popularized by Andrej Karpathy. This repository is an independent joke and is not
affiliated with him.

## Is this legal advice?

No. If you need legal advice, talk to a lawyer.

Because it is the brand. If it is not your vibe, fork it — CC0 means you can.
