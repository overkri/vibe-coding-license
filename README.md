The official manifesto of unreasonable confidence.

VCL is a joke with a purpose: it captures the vibe of building software with AI, intuition, and
absolutely no adult supervision — while staying honest about the boring legal part. It is **not**
a license, it grants **no rights**, and it does not replace MIT, Apache-2.0, or any other real
license.

## The manifesto

Read the full text: [`VIBE-CODING-LICENSE.md`](./VIBE-CODING-LICENSE.md).

Short version:

1. Code may be written with or without understanding.
2. If it works, it works.
3. If it doesn't work, add another prompt.
4. The author is not responsible for bugs caused by excessive confidence.
5. Refactoring is optional. Shipping is mandatory.
6. Coffee, chaos and artificial intelligence are recognized development tools.
7. The right to say «It works on my machine» is irrevocable.

**All vibes reserved.**

## How to use it

1. Keep a real license. For most projects, [MIT](./templates/LICENSE-MIT) is a good default.
   If you need a patent grant, use Apache-2.0.
2. Copy [`templates/VIBE.md`](./templates/VIBE.md) into your project as `VIBE.md`.
3. Add one line to your README:

   ```markdown
   Code: [MIT](./LICENSE). Vibes: [Vibe Coding License 1.0](./VIBE.md) — a manifesto, not a license.
   ```

4. Do **not** rename `VIBE.md` to `LICENSE`, and do **not** remove the real license.

## For learners

If you are learning to code: use VCL as a mindset, not as a substitute for a license.
See [`FOR-LEARNERS.md`](./FOR-LEARNERS.md) for a short, honest guide.

## SPDX

VCL is not an SPDX-standard license and is not OSI-approved. If your tooling absolutely needs an
identifier for the manifesto, use:

```text
LicenseRef-VibeCoding-1.0
```

Keep the code's real license as `MIT` (or `Apache-2.0`). Do not write `MIT AND LicenseRef-...`
as if the manifesto were a license condition; it is not. See [`FAQ.md`](./FAQ.md#what-is-licenseref-vibecoding-10).
